# Sessions, login and Lwt applications

These packages are independently usable. The generic OIDC example assumes a
standards-compliant provider; automated tests use synthetic identities and keys.

| Package | OCaml module | Responsibility |
| --- | --- | --- |
| `httpkit-cookie` | `Httpkit_cookie` | Encrypted cookie sessions and key rotation |
| `httpkit-session-eio` | `Httpkit_session_eio` | Shared PostgreSQL/SQLite sessions |
| `httpkit-password` | `Httpkit_password` | Argon2id hashing, verification and rehash policy |
| `httpkit-oidc` | `Httpkit_oidc` | Authorization-code/PKCE requests and strict ID-token policy |
| `httpkit-oidc-eio` | `Httpkit_oidc_eio` | Browser binding, one-time callbacks and bounded provider requests |
| `httpkit-lwt` | `Httpkit_lwt` | Lwt applications, routing, streaming, middleware, sessions and realtime |

Install these packages from a [pinned source checkout](beta-install.md), then add
their public names to Dune's `libraries` field. They are not on central opam.
Password builds require libargon2, libffi and pkg-config. PostgreSQL bytecode is
[currently blocked](status.md#what-we-found); use native database executables.

## Cookie sessions

```ocaml
module Cookie = Httpkit_cookie

(* Initialize a cryptographically secure RNG once during application startup. *)
let () = Mirage_crypto_rng_unix.use_default ()

let sessions ~secret =
  Cookie.create ~ttl:3600 ~now:Unix.gettimeofday
    ~keys:[Cookie.key ~id:"2026-09" ~secret] ()

let login store user =
  match Cookie.issue store user with
  | Ok session -> Ok (Cookie.set_cookie store session)
  | Error error -> Error error
```

Keys contain exactly 32 CSPRNG-generated bytes. Persist keys securely and share
those keys across instances. Generating a fresh key on every process startup
invalidates existing logins. `generate_key` and `export_key` support provisioning;
never log the exported secret. Put the newest key first and retain previous keys
for at most the remaining session lifetime. `needs_refresh` identifies a session
read with an older key. Rotate keys well before issuing 2^32 cookies under one key
across all instances.

The wrapper invokes Mirage_crypto's AES-256-GCM authenticated-encryption API;
it implements no cipher, MAC or key-derivation algorithm. Nonces and CSRF secrets
come from Mirage_crypto_rng. Version, application cookie name and key ID are
bound to the authentication tag. The token is a bounded version/key-ID/encoded
nonce-and-ciphertext container. Default payloads are at most 2048 UTF-8 bytes;
tokens are capped at 3800 bytes. Cookies are host-only, Secure, HttpOnly,
SameSite=Lax and Path=/.

Use `of_headers` with the request's headers, and add `set_cookie` to the response
as a **new** Set-Cookie field. `clear_cookie` removes the browser's copy.
Cookie data remains replayable until expiry: deleting a cookie does not revoke a
copied token. Use SQL sessions for immediate individual or account-wide
revocation. Use the existing `Httpkit.Auth.csrf` origin/token check with
`Cookie.check_csrf`; SameSite alone does not replace CSRF protection.

## SQL sessions

```ocaml
module Sessions = Httpkit_session_eio

let initialize db =
  Httpkit_db_eio.migrate db [Sessions.migration ~version:1]

let sessions db =
  Sessions.create ~namespace:"my-app" ~ttl:3600 ~now:Unix.gettimeofday
    ~random:Mirage_crypto_rng.generate db

let login store user response =
  let session = Sessions.issue store ~subject:user "application data" in
  Sessions.attach store session response
```

Integrate the exported migration into your **complete ordered migration list**;
do not replace your application's existing migrations. The version number belongs
to that list. Apply it once through the existing checked migration runner.

Instances with the same namespace share sessions. The database contains token
digests rather than bearer tokens. Expiry uses Unix timestamps, so reopening a
pool or restarting an application preserves valid sessions. `rotate` atomically
replaces the token and CSRF secret: concurrent users of the old token have one
winner. `revoke_subject` supports logout across devices. Run `prune` periodically;
it removes a bounded batch and creates no background task itself. Retention and
overall database capacity remain application operational policy.

`require`, `logout` and `protect_csrf` integrate with `Httpkit_eio` handlers.
The memory sessions in `Httpkit_eio.Sessions` remain available for single-process
applications. Each backend has its own opaque session type; application code
chooses its backend explicitly.

## Passwords

```ocaml
module Password = Httpkit_password
let policy = Password.create ()

let hash password =
  Password.hash policy ~random:Mirage_crypto_rng.generate password

let verify ~encoded password = Password.verify policy ~encoded password
```

The default is Argon2id v19 with 64 MiB, three iterations, one lane, a 16-byte salt
and 32-byte output. Stored hashes are checked against hard cost/size bounds before
calling the native library. Passwords are limited to 1024 bytes; empty passwords
and embedded NUL bytes are rejected. Application password-length policy can be
stricter. Call `needs_rehash` after successful verification and replace the stored
hash when policy changes.

These operations are synchronous. Use a bounded pool of **separate OCaml domains**
or worker processes for a web application. The upstream ctypes binding does not
request release of the calling domain's runtime lock; merely putting it in an
Lwt preemptive thread does not establish event-loop responsiveness. Budget workers
against the maximum accepted verification cost (256 MiB per call), not just the
default hashing cost. No runtime-specific password worker pool is supplied.

`examples/passwords/worker.ml` is a small application-owned integration using
Eio's executor pool. It owns one worker domain, admits one job and returns `Busy`
for overlapping submissions. There is no waiting-job queue. Cancellation of a
request retains admission until its already-started job finishes; a cancelled
caller does not receive a successful result. Keep callers within the pool's
owning switch and call the helper from one application domain. Jobs must finish
and access only thread-safe captured values. Native Argon2 cannot be interrupted
mid-call; a request timeout cannot force it to release memory immediately.

```sh
tools/dune-pkg exec examples/passwords/demo.exe
tools/dune-pkg runtest examples/passwords
```

The demo captures secure salt bytes before entering the worker and uses the
existing Argon2 wrapper. It prints no password/hash. The helper is example code,
not a new installed package or a login endpoint. Applications can map `Busy` to
a bounded rejection response and must still budget all other app memory within
their deployment limit. Controlled tests verify separate-domain execution,
admission retention during cancellation, exception cleanup, scope retirement and
a real native hash/verify roundtrip. Sustained mixed-load measurements remain
part of beta acceptance.

The package's small C shim ensures libargon2 is loaded for ordinary bytecode
consumers. It calls no hashing implementation of its own. Account registration,
email verification, password reset, MFA and login throttling are application
features, not implicit parts of the hashing API.

## OIDC

```ocaml
let config =
  Httpkit_oidc.config
    ~issuer:"https://identity.example"
    ~client_id:"registered-client-id"
    ~redirect_uri:"https://app.example/login/callback"
    ()

let coordinator ~clock ~http =
  Httpkit_oidc_eio.create ~clock ~now:Unix.gettimeofday
    ~random:Mirage_crypto_rng.generate ~http config
```

The `http` callback receives a method, URI, headers, body and maximum response
size. Provide your HTTPS client with certificate/hostname validation, redirects
disabled, bounded body reading and Eio cancellation. The coordinator adds
operation deadlines and rejects over-limit responses, but a callback that ignores
its size limit can allocate before that rejection. No TLS implementation is
bundled here.

Mount `Httpkit_oidc_eio.login coordinator` as a GET login endpoint and
`Httpkit_oidc_eio.callback coordinator ~on_login` as the registered GET callback.
`on_login` receives a verified issuer/subject/claims record; issue a cookie or SQL
session there. Treat `(issuer, subject)` as the external account key. An email
claim alone is not an account-linking credential.

The default flow uses authorization code, S256 PKCE, a nonce, one-time state and
a separate Secure/HttpOnly browser-binding cookie. Public clients and
`client_secret_basic` are supported. Client secrets are supplied at startup from
secure configuration. Production URLs must use HTTPS; a separate explicit option
allows HTTP on literal loopback addresses for development.

Metadata is cached for one hour and keys for five minutes. Unknown key IDs can
trigger a refresh at most once per 30 seconds. Pending flows expire after ten
minutes; the store holds at most 1024 flows and permits at most 16 concurrent
remote operations by default. Pending flows are **process-local**: use sticky
routing and accept that a restart cancels outstanding logins. Completed SQL or
cookie sessions can still be shared across instances.

The wrapper accepts RS256 and ES256 only. It rejects duplicate JSON keys,
ambiguous keys, embedded key overrides, unsupported critical headers, wrong
issuer/audience/authorized-party/nonce, future or old issued-at, invalid not-before,
expired tokens and reused callbacks. It uses `oidc` for authorization parameters
and PKCE, and `jose` for signatures/key decoding. It deliberately implements its
own strict claim policy: upstream `oidc` 0.2.0's general validator has an issuer
prefix exception and incomplete `azp` checking, which are unsuitable here.
Refresh tokens, UserInfo calls, provider logout and dynamic client registration
are outside this authorization-code login API.

## Lwt applications

```ocaml
module App = Httpkit_lwt

let application =
  App.routes [
    App.route Httpkit_core.Method.get "/hello/:name" (fun request ->
      let name = Option.value ~default:"world" (App.param "name" request) in
      Lwt.return (App.reply (Httpkit.Reply.text ("Hello " ^ name))))
  ]
```

Request body reads, handlers and streaming producers return Lwt promises. Use
`Httpkit_transport_lwt.monotonic_clock` and provide a cancellable `accept` callback
to `App.serve`. Resolving `stop` stops admission and drains active connections;
cancelling the server cancels and joins handlers and closes owned transports.
Request bodies cannot escape their handler lifetime. HEAD skips streaming
producers. `Common`, `Sessions` and `Realtime` provide middleware, memory sessions,
SSE and bounded WebSocket handling. Filesystem/upload helpers remain Eio-specific.
Neither Lwt applications nor their transport require Eio.

## Verification and dependency sources

`tools/dune-pkg runtest test/extensions` runs the focused controls.
`tools/dev consumer extensions` builds and installs all packages in a
clean project and runs the same controls as native and ordinary `ocamlrun`
consumers, including C-stub loading. The SQL test accepts a database URI for the
existing disposable PostgreSQL/SQLite runner. These are local correctness tests;
they are distinct from an independent security review.

Upstream code and APIs:
[Mirage_crypto](https://github.com/mirage/mirage-crypto),
[Argon2 bindings](https://github.com/Khady/ocaml-argon2),
[OIDC](https://github.com/ulrikstrid/ocaml-oidc),
